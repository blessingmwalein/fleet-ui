# Module specifications

Each module agent implements **its own section** below (plus `docs/ARCHITECTURE.md`). Quality bar: a commercial enterprise SaaS product. All data comes from `useDb`; all mutations go through `useDb` actions (audit-logged, persisted).

Routes are relative to `/`. Sidebar labels live in `src/config/navigation.ts` — the paths there are the contract.

---
## A. dashboard — `features/dashboard`  (route: `dashboard`)
Executive overview. Honour global **date range** and **branch scope**. Page title "Executive overview" + last-updated/live indicator.

**KPI strip** (compact `KpiCard`s, each with value, delta vs previous period via `inPrevRange`, sparkline, status dot, hover hint, click-through `href`):
Total vehicles · Active vehicles (live: moving+idle) · On trip (moving) · Idle · Under maintenance · Offline · Total drivers (active) · Active trips (in_transit+delayed) · Deliveries completed (in range) · Fuel consumption (L in range) · Fleet utilisation % (from `dailyStats` avg in range) · Maintenance expenditure (completed work orders in range).
Live counts come from `useLive` telemetry; period metrics from trips/fuel/workOrders/dailyStats with prev-period comparison.

**Charts** (all interactive: tooltips, legend/series toggles, `Segmented` controls such as day/week/month, metric selectors):
1. Fleet utilisation over time (area/line from `dailyStats`, with active vs in-service vehicles toggle).
2. Fuel consumption trend (litres bars + cost line, dual axis).
3. Vehicle operating costs (stacked: fuel, maintenance, tolls/allowances/other by period).
4. Trips completed vs delayed (stacked/grouped bars by period; delayed = completed with delayMinutes>15 plus currently delayed).
5. Fleet availability distribution (donut: moving / idle / stopped / maintenance / offline from live telemetry).
6. Driver performance (ranked bars or scatter: safety score vs trips; top 5 / bottom 5 toggle).
7. Maintenance cost breakdown (donut by work-order type, or bar by vehicle category toggle).

**Operational panels** (lists with entity links, timestamps, severity badges, "View all" links):
Recent operational activities (audit log + completed trips + live events) · Live fleet alerts (notifications store, unread first, click opens entity) · Upcoming maintenance (schedules due soonest / scheduled work orders) · Expiring documents (documents + driver licences expiring ≤30 days or expired) · Latest incidents · Top-performing vehicles (by utilisation/revenue/km per litre) · Vehicles requiring attention (offline, low fuel <15%, overdue service, expired documents, delayed trips — with reason chips).
Also a compact mini-map card (static list of branch depots with counts or a small live count by region) linking to `/tracking`.
Layout: 12-col grid, dense, no empty areas, responsive stack on mobile. Skeleton on first paint.

## B. vehicles — `features/vehicles`  (routes: `vehicles`, `vehicles/:id`)
**List** (`VehiclesPage`): DataTable of all vehicles (branch-scoped). Columns: Registration, Vehicle (make model year), Category, Assigned driver (link+avatar), Branch, Mileage (odometer — use live telemetry odometer when present), Fuel % (mini bar; live telemetry), Status (live state badge; fallback to admin status), Last location (telemetry.location), Next service (earliest `schedules.nextDueDate`, red when overdue), Actions. Search, sort, pagination, column visibility/resizing (built in), multi-column facet filters (Status[live], Category, Branch, Driver assigned?), CSV export, bulk selection + bulk actions (change status, assign branch, export, delete w/ confirm). KPI mini-strip (total, active, in maintenance, out of service, unassigned). `mobileCard`. Row click → detail page. "Register vehicle" button (+ `?new=1`).
**Workflows** (all with validated `FormDialog`s): Register vehicle (reg format `AAA 1234` unique, make/model/year, category, VIN 17 chars, engine no., fuel type, tank capacity, load capacity, branch, odometer, purchase date/cost, device id; optional driver), Edit vehicle, Assign/unassign driver (updates **both** `vehicle.driverId` and `driver.vehicleId`, unassigning previous holder), Update status (active / maintenance / out_of_service with reason; creating a maintenance work-order option), Schedule maintenance (creates a `workOrders` record, status 'scheduled'), Upload document placeholder (adds a `documents` record with file name/size, expiry), Delete vehicle (confirm; blocked if has an in_transit trip).
**Detail page** (`VehicleDetailPage`): header (plate, make/model, category icon, live status badge, driver, branch, quick actions menu: Edit, Assign driver, Update status, Schedule maintenance, Track on map → `/tracking?vehicle=<id>`, Delete) + KPI row (odometer, fuel, utilisation 30d, cost/km, next service) + `Tabs`:
1 Overview (key facts, current trip card, health/compliance summary, recent activity, mini cost chart) · 2 Specifications (all spec fields, editable) · 3 Live location (live telemetry card + small MapLibre map with marker & route polyline — you may import MapLibre; keep it light, or use a clear static card with coordinates if the map module's helper isn't available) · 4 Trip history (DataTable of the vehicle's trips; links) · 5 Maintenance (work orders + schedules, schedule button) · 6 Fuel history (transactions table + consumption trend chart + L/100km) · 7 Expenses (expenses table + totals by category donut) · 8 Documents (documents with `ExpiryBadge`, upload placeholder, delete) · 9 Incidents (incidents + safety events) · 10 Activity history (audit log entries for this vehicle + trips/work-orders timeline using `Timeline`).
Unknown id → graceful "Vehicle not found" empty state.

## C. drivers — `features/drivers`  (routes: `drivers`, `drivers/:id`)
**List**: DataTable — Driver (avatar+name), Employee no., Licence no., Licence expiry (`ExpiryBadge`), Assigned vehicle (link), Branch, Trips completed (count from trips), Safety score (colored bar/number, ≥85 green, 70–84 amber, <70 red), Status. Facets: Status, Branch, Licence state (expired/expiring/valid), Safety band. Search, sort, paginate, export, bulk (change status, export). KPI strip: total, active, on leave/suspended, licences expiring ≤30d, avg safety score. `mobileCard`.
**Workflows**: Add driver (name, national id, dob, gender, phone, email, address, licence no/class/expiry, defensive-driving & medical expiry, hire date, employment type, branch, salary, emergency contact; validated, licence expiry future-dated warning), Edit driver, Assign/unassign vehicle (keep `vehicle.driverId` ⇄ `driver.vehicleId` consistent), Change status (active/off_duty/on_leave/suspended + reason → audit), Delete (confirm; blocked if on an active trip), Upload document placeholder.
**Detail page** with tabs: Personal info · Employment · Licence & compliance (licence/medical/training expiry cards with `ExpiryBadge`, documents) · Assigned vehicles (current + history from trips) · Trip history (table) · Performance analytics (safety score trend, events per 1,000 km, trips/month, on-time rate, fuel efficiency vs fleet avg, radar/bars) · Safety records (safetyEvents table by type with chart) · Incidents · Documents. Header: avatar, name, status, score ring, quick actions.

## D. trips — `features/trips`  (routes: `dispatch`, `trips`; plus the global `TripDrawerHost.tsx`)
**Dispatch board** (`dispatch`): Kanban with columns **Scheduled · Awaiting assignment · Ready for dispatch · In transit · Delayed · Completed · Cancelled** (statuses `scheduled, awaiting_assignment, ready, in_transit, delayed, completed, cancelled`). Drag-and-drop between columns using `@dnd-kit/core` (installed; pointer + touch + keyboard sensors) which updates trip status via `useDb.update` with validation (e.g. cannot move to *Ready/In transit* without vehicle & driver → open the Assign dialog instead; moving to Delayed asks for reason + minutes; to Completed asks for POD details; to Cancelled asks for reason). Cards: ref, route (origin → destination), cargo, vehicle plate, driver, ETA/progress bar for in-transit (use telemetry), priority badge, delay chip. Completed/Cancelled columns show only the latest 15 with "view all in Trips". Column counts, branch scope, search + filters (priority, vehicle category, customer). Toolbar: "New trip", view toggle Board / List.
**Trips list** (`trips`): DataTable of all trips (branch-scoped, date-range aware): ref, status, route, customer, vehicle, driver, scheduled start, planned vs actual duration, distance, delay, expenses, revenue, margin. Facets (status, priority, cargo type, customer), export, bulk (assign, cancel, export).
**Workflows** (`TripForm` dialog/sheet, reusable): create/edit trip — customer, pickup & destination (pick a **route** from the 21 predefined routes in `data/routes.ts`, which fills origin/destination, planned distance and duration; show route name & road), cargo (type, description, weight), schedule start, vehicle & driver pickers (only available/active; warn when vehicle capacity < cargo weight or driver licence expired or already on a trip), priority, notes; **Assign** dialog; **Dispatch** (→ ready/in_transit; the simulator then drives the vehicle on the map), **Delay**, **Complete** (POD: received by, notes, photos count), **Cancel** (reason), Delete (draft statuses only).
**TripDrawerHost** (global, mounted in the shell; `useUi.tripDrawerId`): full trip detail sheet: header with status + actions, route summary with a small MapLibre preview of the route polyline (and live vehicle position if in transit), progress/ETA (telemetry), timeline (created → scheduled → dispatched → delays → completed), cargo & customer, planned vs actual distance/time, costs (linked expenses + fuel transactions with links) & revenue/margin, POD section, linked shipment, vehicle/driver links, action buttons. Closing sets `openTrip(null)`.

## E. maintenance — `features/maintenance`  (routes: `maintenance`, `maintenance/work-orders`, `maintenance/schedules`, `maintenance/inspections`, `maintenance/providers`)
* **Overview & calendar** (`maintenance`): KPIs (open work orders, overdue services, in workshop now, MTD cost, avg downtime, preventive ratio), **maintenance calendar** (month grid built with date-fns: scheduled work orders & service due dates as colored chips; click day/chip → drawer; month navigation; legend; overdue highlighted), Upcoming & overdue services lists, cost trend chart, cost by type donut, cost-per-vehicle bar list, downtime chart.
* **Work orders** (`maintenance/work-orders`): DataTable (WO no, vehicle, type, title, priority, status, provider, scheduled date, technician, cost, downtime) + facets/bulk/export; request & workflow actions: Request maintenance, Approve, Schedule, Start (sets vehicle status → maintenance), Complete (labour/parts costs, parts used list, odometer → clears maintenance, may create the next service schedule), Cancel; **WO detail drawer** (`?open=`) with parts usage table (qty × unit cost), costs, timeline, vehicle/provider links; `?new=1` opens request form. "Maintenance requests" are work orders in `requested` status — show a dedicated tab/segment for them with approve/reject.
* **Service schedules** (`maintenance/schedules`): preventive schedules per vehicle (task, interval km/days, last service, next due date/km, status Overdue/Due soon/OK computed with odometer & date), service reminders panel, "Create work order from schedule", add/edit/delete schedule (validated), mark serviced (updates last/next).
* **Inspections** (`maintenance/inspections`): table of inspections (result pass/conditional/fail, defects), detail drawer with checklist, "New inspection" form (vehicle, type, checklist toggles, defects → on fail offers to raise a work order).
* **Providers** (`maintenance/providers`): service-provider directory (cards + table; rating stars, specialties, hourly rate, status), add/edit/delete, per-provider spend & job counts, workshop bay capacity view for internal workshops (bays used = in_progress WOs).
* Maintenance cost analysis charts live on the overview (by month, type, vehicle, provider).

## F. fuel — `features/fuel`  (routes: `fuel`, `fuel/transactions`, `fuel/cards`, `fuel/stations`, `fuel/reconciliation`)
* **Overview** (`fuel`): KPIs (litres, spend, avg price/L, fleet avg L/100km, cost per km, flagged transactions) with prev-period deltas; charts: consumption & spend trend (dual axis), fuel efficiency by vehicle category / top & bottom vehicles (L/100km computed from odometer deltas between consecutive fills), cost per km by branch, price per litre by station brand/city, spend by station; **suspicious consumption detection** panel (flagged transactions + rule explanations: tank overfill, odd hours, +X% vs expected, duplicates, odometer mismatch) with Review/Dismiss/Escalate actions.
* **Transactions** (`fuel/transactions`): DataTable with search/facets (vehicle, station, brand, flagged, reconciled), export, add transaction form (`?new=1`; vehicle, driver, station, card, litres, price (prefills from station), odometer; validates litres ≤ tank capacity ×1.1 and odometer ≥ previous), detail drawer (`?open=`) showing the computed expected litres, efficiency, flag reason, receipt, linked trip/vehicle/driver; mark reconciled, delete.
* **Fuel cards** (`fuel/cards`): card table (masked number, vehicle, provider, status, monthly limit, spent, utilisation bar, expiry) + issue/assign/block/unblock/replace/limit-edit actions, spare cards, alerts for near-limit & expired cards.
* **Stations** (`fuel/stations`): station directory with prices (diesel/petrol), approval status, spend/litres per station, price trend, add/edit/suspend; small list of cheapest stations by city.
* **Reconciliation** (`fuel/reconciliation`): month selector; per-vehicle comparison of **purchased litres vs expected litres** (distance from odometer/trips × category L/100km) and **card statement vs recorded transactions**; variance %, status (matched / variance / flagged), bulk "mark reconciled", export; summary cards (matched %, total variance L and $).

## G. shipments — `features/shipments`  (routes: `shipments`, `shipments/:id`, `customers`, `customers/:id`)
* **Shipments list**: DataTable — tracking ref, customer, cargo, pickup → delivery, vehicle, driver, status, ETA/delivered, charge; facets (status, customer, cargo type, branch, exceptions only), status KPI strip clickable as filters, export, bulk (allocate vehicle, export). **Register shipment** (`?new=1`): customer, cargo type/description/weight/packages/declared value, pickup & delivery (pick customer sites or free text + city), pickup window, charge; **Allocate vehicle & driver / create trip** action (creates/links a `trips` record), Update status workflow (picked_up → in_transit → out_for_delivery → delivered; each adds a milestone with timestamp), Raise exception / resolve exception, Capture **proof of delivery** (received by, notes, photo count, condition), Cancel/delete.
* **Shipment detail page** (`shipments/:id`): header (tracking ref, status, customer, copy tracking link/ref), **visual delivery timeline** (milestones, horizontal stepper on desktop + vertical on mobile, exception shown inline), a **MapLibre map** with pickup & delivery markers, route polyline (if trip linked) and the live vehicle marker via telemetry, cargo & charge cards, vehicle/driver/trip links, POD card, exceptions panel, customer contact (call/email buttons).
* **Customers** (`customers`): DataTable — name, industry, city, contact, payment terms, credit limit, outstanding balance (unpaid customer invoices), shipments count, status; add/edit/delete (validated, `?new=1`), on-hold toggle. **Customer detail** (`customers/:id`): profile, KPIs (revenue 90d, outstanding, on-time rate), tabs: Shipments, Trips, Invoices, Activity; edit.

## H. finance — `features/finance`  (routes: `finance`, `finance/expenses`, `finance/invoices`, `finance/budgets`, `finance/profitability`)
* **Overview** (`finance`): KPIs (revenue, operating cost, gross margin %, cost per km, outstanding receivables, payables due, budget variance) with deltas; charts: revenue vs cost trend (+ margin line), cost breakdown donut (fuel, maintenance, tolls, allowances, insurance, other — fuel from `fuelTransactions`, maintenance from completed work orders, others from `expenses`), vehicle operating cost by category, receivables ageing buckets (current, 1–30, 31–60, 61–90, 90+), pending approvals panel, top expensive vehicles, budget-vs-actual mini bars.
* **Expenses** (`finance/expenses`): DataTable (ref, date, category, description, vehicle, trip, driver, amount, supplier, status, submitted by) with facets (category, status, branch), export, `?new=1` submit expense form (links to trip/vehicle; receipt no), **approval workflow**: Approve / Reject (reason) single & bulk, mark Paid; detail drawer (`?open=`); role gating with `finance.approve`. Show totals footer by status.
* **Invoices** (`finance/invoices`): two tabs **Customer invoices (receivables)** and **Supplier invoices (payables)**; DataTable; create customer invoice from completed trips of a customer (select trips → amount auto-sum, due date from payment terms), supplier invoice form, record payment (amount, method, ref → updates paid/status), send/mark sent, overdue highlighting, payment history in a drawer (`?open=`), export.
* **Budgets** (`finance/budgets`): month selector; budget vs actual per category (from live data) with variance bars/colors, over/under badges, edit budget (inline or dialog), add category budget, yearly trend chart.
* **Profitability** (`finance/profitability`): per-vehicle P&L table (revenue from completed trips − fuel − maintenance − expenses = margin; margin %; cost per km; revenue per km) with sort/export/facets (category, branch), scatter or bar chart of margin by vehicle, by customer/route profitability toggle, bottom-5 / top-5 callouts, cost-per-kilometre analysis chart by category.

## I. safety — `features/safety`  (routes: `safety`, `safety/incidents`, `safety/behaviour`, `safety/compliance`)
* **Overview** (`safety`): KPIs (incidents in range, severity-weighted risk score, harsh events per 1,000 km, speeding events, expiring documents, non-compliant vehicles), charts: safety events trend by type (stacked), incidents by type & severity, risk heatmap (day-of-week × hour or region), driver risk league table (score, events, incidents; coaching suggested chip), compliance status donut; live feed of latest safety events (updates as the simulator raises speeding/harsh events).
* **Incidents** (`safety/incidents`): incident register DataTable + facets (type, severity, status, branch), `?new=1` **Accident/incident report** form (vehicle, driver auto-filled from vehicle, trip, date/time, location, type, severity, injuries, third party, police report no., description, est. cost, insurance claim), detail drawer (`?open=`) with workflow (Reported → Investigating → Resolved → Closed), root cause & actions taken, linked trip/vehicle/driver, location mini-map, costs, close/reopen, delete.
* **Driver behaviour** (`safety/behaviour`): events table (harsh braking, harsh acceleration, speeding, fatigue, cornering, seatbelt, phone use, idling) with filters, review/acknowledge action, driver scorecards (cards or table with score computed from events per distance, trend sparkline, top offending event), coaching action (creates an audit entry + toast), fatigue alerts (continuous driving hours), speeding analysis (over-limit distribution chart).
* **Compliance** (`safety/compliance`): unified register of `documents` (vehicle insurance, roadworthiness, vehicle licence, route permits…, driver licence, medical, defensive driving) with expiry state (expired / expiring ≤30d / valid via `expiryState`), facets (type, entity type, state, branch), compliance score KPIs, **compliance reminders** list (send reminder = toast + audit; snooze), renew action (update expiry date & upload placeholder), add document, vehicle inspection records summary (link to maintenance inspections), `?open=` drawer for a document. Insurance expiry / licence expiry / roadworthiness each get a segmented tab view with counts.

## J. reports — `features/reports`  (routes: `reports`, `reports/:category`)
**Report centre** (`reports`): grid of the 10 report cards (icon, description, last-run info, "Open") grouped by Operations / Fleet / Finance / Safety, plus a "Recent exports" list (kept in component state/localStorage).
**Report page** (`reports/:category`, slug ∈ `fleet-utilisation, vehicle-performance, driver-performance, trip-performance, delivery-performance, fuel-consumption, maintenance-costs, operating-expenses, safety-incidents, financial-performance`): a consistent `ReportLayout` with: title/description, **working** controls — date range (defaults to the global range but locally overridable via presets + custom dates), **group by** (day/week/month and/or vehicle/driver/branch/category/customer as applicable), branch filter, optional metric toggle; summary KPI strip; 1–2 interactive charts; a detailed `DataTable` (grouped rows computed from real data) ; **Export CSV** (and a "Print / PDF" button that opens `window.print()` with print-friendly CSS). Each category must produce **meaningful, distinct analytics** from the dataset (e.g. fleet utilisation by vehicle & period; vehicle performance: km, trips, revenue, cost/km, availability; driver performance: trips, on-time %, safety score, events, fuel efficiency; trip performance: completion, delays by reason, planned vs actual; delivery performance: on-time delivery %, POD, exceptions by customer; fuel: L, spend, L/100km, anomalies; maintenance: cost by vehicle/type/provider, downtime; operating expenses: by category/branch/vehicle; safety: incidents/events by driver/type; financial: revenue, costs, margin, receivables). Unknown slug → "Report not found". Build shared helpers in `features/reports/lib`.

## K. admin — `features/admin`  (routes: `admin` (redirects to users), `admin/users`, `admin/roles`, `admin/organisation`, `admin/notifications`, `admin/audit`, `admin/settings`)
* **Users** (`admin/users`): DataTable (avatar, name, email, role, branch, department, status, 2FA, last login), invite/add user (validated, `?new=1` not required), edit, change role, enable/disable, reset password (toast), delete (confirm; cannot delete self); detail drawer (`?open=`) with permissions summary & recent audit activity. Gate with `admin.*` permissions.
* **Roles & permissions** (`admin/roles`): role list + a **permission matrix** (modules × view/create/edit/delete/approve/export checkboxes from `config/permissions.ts`), create custom role (clone from existing), edit (built-in roles editable but warn), delete custom role (blocked if in use), live preview of what the sidebar will show for that role ("Preview as role" button switches session user to someone with the role); changes persisted via `useDb`.
* **Organisation** (`admin/organisation`): tabs **Branches & depots** (table + map-less cards, add/edit/delete/deactivate, capacity & vehicles-per-branch stats, manager, `?branch=` highlight), **Departments** (CRUD, headcount, cost centre), **Geofences** (CRUD: name, kind, centre lat/lng, radius, alerts toggles — used by the GPS simulator & map).
* **Notification preferences** (`admin/notifications`): matrix of notification types × channels (in-app / email / SMS) bound to `useSettings().notificationPrefs`/`setChannel` (in-app really suppresses notifications), thresholds (low-fuel %, document expiry warning days, idle minutes, harsh-brake g, max drive hours via `setThresholds`), quiet hours (local state), a **"Send test notification"** button that publishes to `eventBus` (`services/events`).
* **Audit log** (`admin/audit`): DataTable of `auditLog` (time, user, action badge, entity type, entity link when resolvable, summary), facets (user, action, entity), date range, export; detail drawer showing raw entry.
* **Settings** (`admin/settings`): tabs **General** (timezone, units display, date format – persisted in `useSettings`/local), **Company information** (`useSettings().company` form), **Currency** (USD ↔ ZiG toggle + `zwgRate` editor with live preview of formatted examples), **Simulation** (`useSettings().simulation`: enable/disable, GPS interval ms, time-scale multiplier slider, events on/off; clear label that telemetry is **demo data**), **Data** (Reset demo data → `resetDemoData()` with confirm; export/import settings JSON; storage usage).
